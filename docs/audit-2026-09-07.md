The critical Vitest advisory is **conditional developer exposure**, not evidence that the deployed static app permitted code execution. Its stated conditions involve exposing the UI/API server or running affected browser/UI modes on Windows; this repo used `vitest run`. The affected package was nevertheless replaced. Sources: [Vitest advisory](https://github.com/advisories/GHSA-5xrq-8626-4rwp), [Vite advisory](https://github.com/advisories/GHSA-fx2h-pf6j-xcff).

The registry audit’s dependency total fell from 460 to 361. These are tool-reported dependency counts, not browser bundle sizes. The main application bundle remains about **89.4 kB gzip**; the Graphviz worker and Stockfish assets load separately. A zero-advisory result is a dated registry check, not a guarantee against undiscovered vulnerabilities.

## Validation

- **19 unit tests passed**, including the five new regression cases for import boundaries, queued analysis and worker recovery.
- **9 Chromium browser tests passed**, including actual Stockfish analysis, complete replay and stable positions, deeper branch exploration, cache reopening, import errors, custom FEN/promotion, desktop/mobile layout, and live Chess.com/Lichess imports. Chess.com returned 14 public games during this check.
- **TypeScript, ESLint, formatting and production build passed.**
- The independent Figure 5 check remains at **8.99% color difference, 96.97% ink precision and 92.33% ink recall**, within its existing thresholds.
- README content was rendered through GitHub’s Markdown API and visually checked at desktop and 390px width, on light and dark backgrounds. Images resolve, the page does not overflow, and the replay has a still-image fallback for reduced-motion preferences.
- A fresh temporary copy passed frozen-lockfile installation, all checks and a production build on Node 24, using the downloaded package cache. This verifies that the application does not rely on untracked engine binaries or the existing `node_modules` directory.

## Remaining work

These are follow-up scopes, not completed claims or regressions introduced by this change.

1. **Accessibility pass.** The graph’s tab order primarily exposes the selected glyph, while candidate buttons expose first moves. Keyboard access to every deeper junction, visible focus through SVG selection, announcements, and the contrast of tiny secondary labels need a dedicated pass. No WCAG conformance claim is made.
2. **Large-game and repeated-exploration budgets.** The 600-half-move import limit is not a demonstrated responsiveness guarantee. PGN parsing and display-graph preparation still run on the main thread; there is no global cap for repeated manual exploration. Benchmark long games and repeated expansion on representative phones before setting budgets or moving more work into workers.
3. **Merged-junction route selection.** Histories remain separate and legality tests cover them, but a shared glyph does not yet provide an explicit picker for all the routes that reach it. Add that UI before promising complete navigation of every occurrence.
4. **Cross-browser verification.** This audit exercised Chromium. Run the worker, IndexedDB, import and SVG interaction suites on Firefox and Safari/iOS before advertising broader browser support.
5. **Deployment and maintenance.** There is no production deployment configured. Root-path static hosting, an SPA fallback and appropriate WASM handling are documented, but hosting-provider behavior, response headers, dependency-update policy and required branch checks still need to be selected and verified. The new workflow does not itself enable branch protection.

The paper’s recovered artwork retains its original rights and remains clearly separated from legal game data. Stockfish’s license and corresponding source are linked. The [attribution document](ATTRIBUTION.md) records provenance; it does not grant new rights to the source artwork.
